**贯穿案例 · 林小满**

"小满烘焙"订货系统在林小满的电脑上跑得很欢：选面包、选时间、下单，一气呵成。她兴冲冲地给在外地的女儿打视频："你打开看看！"女儿问："网址呢？"林小满愣住了——她的网站只活在自己的电脑上，地址是 localhost:3000，出了这台电脑，谁也打不开。

那天晚上她没睡好。第二天，她把网站"搬"到了网上：注册 Vercel，连上 GitHub，点了几下，一个真正的网址诞生了。她把链接发到顾客群，配了一句话："小满烘焙网上订货，开张了！"当晚 11 点，第一单进来了——邻居王阿姨订了明早 8 点的碱水包。

从"我的电脑能跑"到"全世界能打开"，中间只隔了一个词：**部署**。这一章，就讲怎么把你的网站搬上网。

## 11.1 从你的电脑到全世界

先搞懂"部署"这个词。你的网站现在住在你的电脑里，只有你的电脑能看见。部署，就是**把它搬到一台 24 小时开机的电脑上，让所有人都能通过网址访问**。那台 24 小时开机的电脑，叫**服务器**；提供服务器、帮你管它的服务，叫**托管**。

打个比方：你的网站现在是"在家招待朋友"，部署就是"租个店面开张"。在家招待，你出门了客人就进不来；开了店，半夜三点也有人能下单——王阿姨那单就是半夜 11 点下的。

所以部署要解决三件事：找个地方放网站（托管）、给它一个大家记得住的地址（域名）、以后改了代码能方便地更新（发布流程）。一件一件来。

## 11.2 Vercel：一键上线

Vercel 是个托管平台，对 Next.js 项目友好到离谱——因为它就是做 Next.js 的那家公司开的。流程简单到不像"部署"：

1. 把代码推到 GitHub（第 10 章你已经会了）。
2. 打开 Vercel 网站，用 GitHub 账号登录，点"导入项目"，选中你的仓库。
3. 点"部署"，等一两分钟。

完事。你会得到一个网址，比如 `xiaoman-bakery.vercel.app` 这样的（以实际生成的为准）。把它发给朋友，手机、电脑都能打开。

还有两个甜点功能。第一，**预览链接**：以后你改代码、提 PR，Vercel 会自动给这次改动生成一个临时网址，不用上线就能先看效果，发给朋友尝鲜。第二，**自动 HTTPS**：网址前面那把小绿锁，Vercel 免费给你配好，用户看着放心，你不用管什么证书。

林小满就是这么上线的。从点"部署"到把链接发进顾客群，不到十分钟。她说："我以为上线是工程师的活，没想到比发朋友圈还简单。"

## 11.3 域名：你的门牌号

`xiaoman-bakery.vercel.app` 能打开，但不够"像个店"。你想要的是 `xiaomanbakery.com` 这样的**域名**——你的网上门牌号，好记、好看、是自己的资产。

去哪买？找**域名注册商**（比如阿里云万网、腾讯云 DNSPod、Cloudflare Registrar、国外的 Namecheap，随便哪家都行）。搜你想要的名字，没被注册就能买，按年付费，到期记得续。

买完之后做**绑定**：在 Vercel 项目设置里填上你的域名，它会给你几条 **DNS 记录**——DNS 就是"门牌号和实际地址的对照表"，你把这几条记录填到域名注册商那边，等几分钟到几小时，全球就都知道"这个门牌号指向你的网站"了。

绑完记得检查两件事：浏览器地址栏有没有小绿锁（HTTPS），手机上能不能打开。都 OK，你的店就算有了正式招牌。林小满的域名是女儿帮她挑的，绑定那晚，她把新网址又发了一遍顾客群："认准这个，以后都在这儿下单。"

## 11.4 改完代码，不用半夜爬起来

网站上线不是终点，是起点。以后你要加功能、改价格、修 bug，总不能每次都手动重复"打包、上传、重启"那套吧？

这就是 **CI/CD** 要解决的事。拆开说：CI（持续集成）是"代码一提交，自动检查、自动构建"；CD（持续部署）是"构建通过，自动上线"。连起来就是：**你在电脑上改完代码，push 到 GitHub，剩下的全自动**——Vercel 检测到新代码，自动构建、自动部署，几分钟后线上就是新版本。

对林小满来说，这意味着：白天在店里想到"碱水包涨价 1 块钱"，改个数字，push，喝杯茶的工夫，网上的价格就变了。不用开电脑连服务器，不用半夜爬起来"发布"。

还有个救命功能叫**回滚**：某次更新改出 bug 了，在 Vercel 后台点一下"回到上一个版本"，网站瞬间恢复。记住这句话：**敢上线，是因为能回滚**。没有回滚的发布，都是裸奔。

## 11.5 其他路：Netlify、Cloudflare

Vercel 不是唯一选择，知道有这几条路就行：

**Netlify**：和 Vercel 一个思路，也是连 GitHub、一键部署。它起家做静态网站，表单、函数这些配套很顺手。如果你的项目以后不走 Next.js 了，它是个好备选。

**Cloudflare**：除了能托管（Cloudflare Pages），它真正的看家本领是**CDN 和防护**——CDN 就是把你的网站复制到全球各地的机房，用户从最近的地方打开，速度快；防护就是帮你挡恶意流量。网站做大了、用户多了，再来研究它不迟。

一句话总结：小项目，Vercel 或 Netlify 闭眼选一个；等你真有了"全球用户"，再请 Cloudflare 出马。现在，别为没发生的问题操心。

## 11.6 在国内上线：Vercel 跑不顺怎么办

上面讲的 Vercel 有个前提：你的用户能顺畅访问它。但如果你和用户都在国内，会发现 Vercel 的网站**时快时慢，甚至打不开**——它的服务器主要在海外，中间这段路不太稳。这不是你的错，是路的问题。

国内读者的对应方案：

**静态网站 → GitHub Pages / Cloudflare Pages**：和 Vercel 一个思路，连 GitHub 自动部署。GitHub Pages 在国内能打开（偶尔慢），Cloudflare Pages 配上它的 CDN 国内体验也不错。本书的示例项目「小满烘焙」演示站就是放在 GitHub Pages 上的。

**要数据库、要后端 → 腾讯云 CloudBase / 阿里云**：前面第 8 章说的"云数据库"，国内就用这一家。CloudBase 一站式搞定：静态托管放前端、云数据库存订单，免费额度一家小店够用。它的控制台和文档都是中文，对零基础更友好。

**域名**：国内域名要**备案**才能指向国内服务器——在腾讯云/阿里云买域名，跟着它们的备案指引走一遍就行，一般两周左右。嫌麻烦就先用平台送的免费二级域名（比如 xxx.tcb.qcloud.la），跑起来再说。

一句话：人在国内，部署就选国内的路——Pages 类管前端、CloudBase 管数据，和 Vercel 那套一一对应，只是换了个更顺的道。

## 11.7 什么时候才需要 Docker

你可能听过 **Docker**，用人话讲：它是个"集装箱"——把你的网站和它运行需要的环境（Node 版本、系统库、配置）一起打进一个箱子，搬到哪台服务器，打开箱子就能跑，绝不会出现"在我电脑上明明好好的"这种事。

听起来很美，但现阶段你**用不上**。Vercel、Netlify 这类平台已经帮你把"环境"管好了，你只管 push 代码。Docker 是给"自己租服务器、自己管环境"的人准备的，那是第 14 章"规模化"之后才要操心的事。

记住这个顺序：先用托管平台把店开起来，等哪天平台满足不了你了（比如要跑特殊服务、要省成本），再学 Docker 不迟。**工具是为阶段服务的，别提前为未来交学费。**

## 本章要点

1. 部署 = 把网站从你的电脑搬到 24 小时开机的服务器上，让所有人能用网址访问。
2. Vercel 连 GitHub，一键上线，还送预览链接和免费 HTTPS。
3. 域名是你的网上门牌号：注册商购买 → 填 DNS 记录绑定 → 检查小绿锁。
4. CI/CD = push 代码后自动构建、自动上线；敢上线是因为能一键回滚。
5. Netlify 是备选，Cloudflare 是网站做大后的加速和防护，Docker 是自己管服务器时才需要的集装箱——现阶段都不用碰。人在国内的话，部署走国内路线：GitHub/Cloudflare Pages 管前端、腾讯云 CloudBase 管数据。

## 动手 Kata

1. 把你的项目连上 Vercel，拿到公网链接，用手机打开走一遍下单流程。
2. 把链接发给 3 个朋友，让他们在各自的手机上打开，收集"打不开/显示怪"的问题。
3. （可选）买一个域名，绑定到你的项目上，检查小绿锁。
4. （可选）故意改一行文字，push，观察 Vercel 自动部署的全过程，再点一次"回滚"试试手感。

## 翻车现场

老王看林小满上线眼红，也想把自己的"社区团购"网站搬上网。为了省钱，他把网站装在家里一台旧笔记本上，还美其名曰"自己的服务器"。开张第三天，小区停电半天，网站跟着黑了半天，群里几十个人问"链接怎么打不开了"，他一边道歉一边爬起来给笔记本充电。

他省下的是托管的钱，赔掉的是所有用户的信任。教训很直白：**生产环境别放在自己家里**。专业的事交给托管平台，你的旧笔记本就让它好好退休。
