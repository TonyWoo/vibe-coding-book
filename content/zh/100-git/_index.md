**贯穿案例 · 林小满**

那是林小满最崩溃的一个晚上。

她的订货网站跑起来一个月了，邻居们用得挺顺。那天她突发奇想，让 AI "把首页做得喜庆一点，红色，大字，热闹"。AI 吭哧吭哧改了二十分钟——首页确实红了，红得像婚庆公司开业；更要命的是，菜单页的"放进篮子"按钮点不动了，订单页还少了一块。

"改回去！"她喊。但怎么改回去？AI 早忘了原来长什么样，她自己更说不清。她对着屏幕发了半小时呆，第一次体会到：**AI 改代码比人快，改崩了也比人快**。

那天晚上，她学会了 Git。从那以后，她每天收工都 commit，代码推到 GitHub，再也没丢过东西。她说："Git 是我请的最便宜的保险。"

## 10.1 后悔药：版本管理是什么

先说人话：**版本管理就是游戏存档**。

你打 Boss 之前先存个档，打输了读档重来，不丢进度。写代码也一样：每次改出一个"能跑"的状态，就存一个档；改崩了，读档，回到能跑的那一刻。

没有版本管理是什么体验？改之前好好的，改之后全坏了，你想找回原来的样子——只能凭记忆重写。AI 时代更惨：AI 一次改十个文件，它自己都不记得原来长什么样，你问它，它一脸无辜："要不我再改改？"

有了版本管理，画风就变了：**代码也有了"撤销"键，一次能撤销一整天**。这就是 Git 要给你上的保险。

## 10.2 Git 三件套：提交、查看、回退

Git 是什么？一个装在你电脑上的免费小工具，专门管存档。你不用背它的原理，会三个动作就行——让 AI 帮你敲命令，你负责理解在发生什么。

**第一式：提交（commit），就是存档。**

```bash
git add .
git commit -m "首页改成暖色风格"
```

第一行是"把改动收拢"，第二行是"存档"。`-m` 后面那句话是给未来的你留的纸条，写人话："首页改成暖色风格"比"update"强一百倍——三个月后你只认识人话，不认识 update。

**第二式：查看（log），就是翻存档列表。**

```bash
git log --oneline
```

列出你存过的所有档，一行一个，带时间。想知道"上周三那个能跑的版本"是哪个，翻它。

**第三式：回退，就是读档。**

改崩了？挑一个能跑的存档点，读档。命令让 AI 帮你执行，你只要说清楚："回到昨天晚上那个版本。"十秒钟，世界清净了。

林小满现在的流程：每次让 AI 大改之前，先 commit 存个档，再让 AI 放手折腾。改好了，皆大欢喜；改崩了，10 秒回档。她说这叫"先存档再打 Boss"，打了几十年游戏的经验，终于用上了。

## 10.3 分支：平行宇宙里试错

分支（branch）是什么？**平行宇宙**。

你的主宇宙叫 main——那是正在营业的店，客人正在下单，绝对不能乱。你想试"红色喜庆风"？别在主宇宙里折腾，开一个平行宇宙（分支）进去试。试好了，把成果搬回主宇宙（合并）；试崩了，把这个宇宙一删，主宇宙毫发无伤。

用人话说分支的三步：

1. 开分支：`git checkout -b 试试红色`——进小房间。
2. 随便折腾：让 AI 可劲儿改，炸了不心疼。
3. 合并或删除：满意就合并回 main，不满意删分支，当没来过。

铁律只有一条：**main 分支永远是"能跑"的版本**。这是你和 AI 之间的约定，也是你和未来自己的约定。实验再疯，也别在 main 上直接动手。

林小满现在有三个常驻分支：`main`（营业中）、`试新功能`（折腾区）、`节日版`（春节、国庆换皮肤用）。她说："以前改代码像走钢丝，现在像在游乐场——摔下来有垫子。"

## 10.4 推到 GitHub：云端保险箱

Git 和 GitHub 是两回事，别弄混：

- **Git**：你电脑里的存档工具，离线也能用。
- **GitHub**：网上的保险箱，全世界程序员存代码的地方。

`push` 就是"把本地的存档复印一份，放进云端保险箱"；`pull` 反过来，是"从保险箱取一份到本地"。两个人记住这俩词，够用了。

为什么非要推到云端？三个理由，一个比一个实在：

1. **电脑会坏。** 硬盘坏、电脑丢、咖啡泼键盘——本地存档再全，也抵不过一次硬件故障。云端那份才是真正的保险。
2. **换设备接着干。** 家里电脑、店里电脑，pull 一下，代码就跟过来了。
3. **给别人看。** 以后找人帮忙、找人接手，发个链接就行，不用 U 盘拷来拷去。

一个人也要养成习惯：**每天收工 push，早上开工 pull**。就当是锁店门——每天都做，不做睡不着。

林小满的代码现在躺在 GitHub 上。她说："比存银行还安心，银行还可能倒闭呢。"

## 10.5 好习惯：每天收工 commit

工具会了，剩下的是习惯。三个习惯，背下来：

**习惯一：大改之前先存档。**
让 AI 动大手术前，先 commit。原话模板："先帮我 commit 一下，备注'改首页之前'，再开始改。"——把 AI 也纳入流程，它不会觉得你啰嗦。

**习惯二：每天收工 commit + push，日结不隔夜。**
不管今天改了多少，收工前存档并推到云端。电脑一合，万事不愁。最忌讳"我明天再提交"，明天有明天的改动，攒在一起，存档就失去了意义。

**习惯三：commit 信息写人话。**
"把取货时间改成按钮"——好；"fix bug"——坏；"update"——等于没写。记住：这条信息是写给三个月后的你看的，那时候的你，已经忘了今天发生过什么。

这三个习惯加起来，一年多花不了你两个小时，换来的是：**再也没丢过东西**。林小满的原话："以前丢文件靠运气找回来，现在靠 Git——我选择相信 Git。"

## 本章要点

1. 版本管理 = 游戏存档，改崩了能读档重来。
2. Git 三件套：commit 存档、log 翻记录、回退读档——命令让 AI 敲，你负责懂。
3. 分支是平行宇宙：main 永远保持"能跑"，实验去分支里做。
4. GitHub 是云端保险箱：push 是复印存档，pull 是取回来；每天收工 push。
5. 三个习惯：大改前存档、日结不隔夜、commit 写人话。

## 动手 Kata

1. 在你的项目文件夹里 `git init`，然后第一次 `git commit`——存下你的第一个档。
2. 故意改坏一个文件（比如删几行），再用回退找回来。亲手体验一次"后悔药"，比看十遍管用。
3. 开一个分支叫 `试试红色`，让 AI 把首页改成红色主题：满意就合并回 main，不满意删分支。
4. 注册一个 GitHub 账号，把代码 `push` 上去，截图发给朋友炫耀一下。

## 翻车现场

小马是林小满顾客群里的宝妈，跟着书写到第 5 章，做了个亲子阅读记录的小程序，两个月的心血，代码只在她自己电脑上。她总想着"明天再备份"。

某天早上，电脑蓝屏，开不了机。修电脑的拆开一看：硬盘坏了，数据全没。小马坐在维修店门口哭了十分钟——两个月，归零，一行都没剩。

她后来逢人就说一句话："我不是输给了技术，是输给了'明天再备份'。"

教训只有一句：**没 push 的代码，就是没写过的代码。** 电脑一合，先 push 再关机。
